# 표기와 규약

이 프로젝트의 모든 유도가 따르는 약속. 새 레이어를 유도하기 전에 한 번 읽어 둔다.

여기 나오는 `Linear` 같은 이름은 아직 `src/`에 없다. 노트북을 진행하며 만들게 되는데,
그때 이 규약을 따르면 나중에 서로 맞물린다.

## 모양 규약

| 기호 | 모양 | 뜻 |
|---|---|---|
| `x` | `(N, D_in)` | 입력 미니배치. 첫 축이 배치. |
| `W` | `(D_in, D_out)` | 선형층 가중치. `x @ W`로 쓰기 위해 이 순서다. |
| `b` | `(D_out,)` | 편향. 배치축으로 브로드캐스팅된다. |
| `dout` | `y`와 같은 모양 | 상류 기울기 `∂L/∂y`. |

`L`은 항상 **스칼라** 손실이다. 그래서 임의의 텐서 `A`에 대해 `∂L/∂A`가
`A`와 같은 모양을 갖는다 (분모 배치, denominator layout). 파라미터 객체에서
`p.grad.shape == p.data.shape`가 항상 성립하는 이유다.

## 우리가 실제로 계산하는 것

레이어는 함수 `y = f(x)`이고, 그 미분은 야코비안 `J = ∂y/∂x`다. 하지만 야코비안을
직접 만들지 않는다. `x`가 `(N, D)`이고 `y`가 `(N, K)`면 야코비안은 `(N·K) × (N·D)`
행렬이라, MNIST 크기만 되어도 메모리에 올라가지 않는다.

대신 항상 **야코비안-벡터곱** 하나만 계산한다.

```
backward(dout) = Jᵀ · dout      (∂L/∂x = (∂y/∂x)ᵀ ∂L/∂y)
```

역전파가 빠른 이유가 이것이다. 스칼라 손실에서 시작하므로 오른쪽부터 곱해 나가면
행렬-벡터곱만 하면 되고, 야코비안이 명시적으로 나타날 일이 없다.
`backward`를 짤 때 목표는 `Jᵀ·dout`을 **닫힌 형태로 정리하는 것**이다.
`Linear`에서 그것이 `dout @ W.T`로 나오는 것처럼.

## 자주 쓰는 두 가지 규칙

**1. 브로드캐스팅된 축은 backward에서 합이 된다.**

forward에서 하나의 값을 여러 곳에 복사했다면, backward에서는 그 복사본들의
기울기를 모두 더해서 되돌린다. 편향 `b`가 배치 전체에 더해지므로
`db = dout.sum(axis=0)`인 것이 그 예다. 같은 원리가 CNN의 가중치 공유,
RNN의 시간축 전개, Transformer의 가중치 공유에 그대로 적용된다.

**2. 성분별 함수의 야코비안은 대각이다.**

`y_i = g(x_i)`처럼 각 성분이 자기 자신에만 의존하면 `J = diag(g'(x))`이고,
`Jᵀ·dout`은 행렬곱이 아니라 성분곱 `g'(x) ⊙ dout`이 된다. ReLU, Sigmoid,
Tanh, GELU가 모두 이 경우다.

이 규칙에서 벗어나는 것이 softmax, LayerNorm, BatchNorm이다. 정규화 때문에
각 출력이 **모든** 입력에 의존하므로 야코비안이 대각이 아니다. 그래서 유도가 어렵고,
그래서 그 세 개가 이 프로젝트에서 가장 배울 것이 많은 레이어다.

## 검증

유도를 마치면 반드시 수치미분과 대조한다.

```python
from src import check_function, check_layer

# 아직 함수 쌍일 때 (노트북 초반)
check_function(forward_fn, backward_fn, x)

# Layer 로 정리한 뒤
check_layer(MyLayer(), x, verbose=True)
```

올바른 유도는 상대오차 `1e-9` 언저리가 나온다. `1e-3` 이상이 나오면 유도가 틀렸다.
그 사이 애매한 값이라면 대개 다음 중 하나다.

- 꺾인 점 근처의 입력 (ReLU에서 `x ≈ 0`) — 그 값을 피해서 다시 검사한다.
- `float32` 사용 — 이 프로젝트는 `float64`로 통일한다. `float32`에서는
  잡음 바닥이 `1e-3` 수준까지 올라와 실제 유도 오류와 구분되지 않는다.
- 캐시 오염 — `forward`가 남긴 상태를 `backward`가 잘못 참조하고 있다.
