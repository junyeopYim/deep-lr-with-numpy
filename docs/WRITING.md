# 노트북 글 규칙

읽는 사람은 딥러닝을 처음 시작하는 사람입니다. Python의 변수·함수·반복문은 읽을 수 있지만
"입력", "가중치", "MNIST" 같은 말은 모른다고 가정합니다. 이 문서는 그 독자가
**어느 부분에 힘을 쓰고 어느 부분을 넘어가도 되는지**, 그리고 **낯선 말을 만났을 때 바로 그 자리에서 뜻을 알 수 있게**
노트북을 쓰는 규칙입니다. 그림 규칙은 [DESIGN.md](DESIGN.md)에 있습니다.

## 1. 중요도 표시

마크다운 셀은 첫머리에 아래 표시 중 하나를 붙입니다. 코드 셀에는 붙이지 않습니다. 앞의 마크다운 표시가 그 뒤 코드 셀에도 적용됩니다.

| 표시 | 뜻 | 무엇을 여기에 두나 |
|---|---|---|
| `🔑 **핵심** · ` | 이 노트북이 가르치려는 수식·규칙·코드 | 절의 정의와 수식, 핵심 함수, shape 규칙 |
| `🔍 **확인** · ` | 실행하고 눈으로 보는 것 | 검산 결과 해석, 그림 해석, "바꿔 보기" |
| `📎 **참고** · ` | 처음에는 건너뛰어도 되는 것 | 배경 지식, 환경·다운로드, 용어의 유래, 다른 노트북과의 연결 |
| `✏️ **연습** · ` | 직접 바꿔 보는 문제 | 절 연습(🔑 절마다 하나), 연습 A·B·C, 준비도 질문 |

- 제목 셀은 표시를 제목 줄 안에 넣습니다: `## 🔑 1. 숫자 두 개에서 출발합니다`, `### 🔍 같은 내적을 이미지에서 보면`. 표시를 제목 앞 같은 줄에 두면 제목이 렌더링되지 않습니다.
- 상황을 잇는 두 줄기를 노트북 맨 위 📎 셀에서 소개합니다. 00–04는 **과일**(붉기·무게·당도·익음)과 **MNIST**(고정 예시 10장, 학습 5,000장, "7인가")입니다. 새 변수 이름은 `mnist_` 접두어를 붙여 본문의 변수와 충돌하지 않게 합니다.
- 🔑 셀은 제목 바로 아래에 **"이 절에서 가져갈 것:"** 한 문장을 둡니다. 절을 다 읽은 뒤 이 문장을 자기 말로 다시 말할 수 있으면 넘어갑니다.
- 노트북 맨 위에는 "읽는 법" 표와 **"이 노트북에서 반드시 가져갈 세 가지"**를 둡니다. 준비도 질문은 🔑 절의 내용만으로 답할 수 있어야 합니다.
- 한 노트북에서 🔑는 절 수 이하로 유지합니다. 전부 핵심이면 표시가 의미를 잃습니다.
- **🔑 절마다 예시 그림을 최소 하나 둡니다.** 그 절의 "가져갈 것" 문장을 눈으로 보여 주는 그림이어야 하고, 절의 상황(과일)이나 고정 MNIST 예시를 씁니다. 검산 오차 막대나 학습 곡선은 이 하나로 세지 않습니다. 그림은 🔑 설명 **바로 뒤**에 둡니다(절의 끝이 아니라). 그림 바로 아래 🔍 셀에 "무엇을 보라"는 한두 문장을 두고, 그다음에 구현과 검산이 옵니다. 그림의 종류와 부품은 [DESIGN.md](DESIGN.md)를 따릅니다.

## 2. 용어는 처음 나오는 자리에서

- 새 용어는 처음 등장하는 셀에 **용어 상자**로 풀이합니다. 뒤에 따로 모은 용어집을 두지 않습니다.
- 형식은 인용 블록 안의 목록입니다. 항목 하나에 용어 하나, 한 문장에서 두 문장으로 씁니다. 용어가 하나뿐이면 `> **용어** · **뉴런(neuron)**: …` 한 줄로 씁니다.

  ```markdown
  > **용어**
  >
  > - **가중치(weight)** $w$: 입력마다 하나씩 붙어서 "이 입력을 얼마나 중요하게 볼지"를 정하는 숫자. 곱해서 씁니다.
  > - **편향(bias)** $b$: 입력과 상관없이 마지막에 더하는 숫자. 점수의 기준점을 옮깁니다.
  ```

- 풀이는 **무엇인지**와 **코드에서 어떻게 나타나는지**를 함께 적습니다. 예: "내적: 같은 위치끼리 곱해 더한 숫자 하나. 코드에서는 `x @ w`".
- 한글 이름 뒤에 영어 원어를 괄호로 한 번만 적습니다. 이후에는 한글만 씁니다. 수학 기호는 기호 그대로 둡니다.
- 데이터셋(MNIST 등)도 용어입니다. 무엇을 담고 있고 왜 이 예제에 쓰는지 한두 줄로 적습니다.

## 3. 절의 첫 문단은 상황에서 시작

- 수식을 꺼내기 전에 **손에 잡히는 상황** 한두 문장을 둡니다. 00은 "과일의 붉기와 무게로 익은 정도 점수를 매긴다"로 시작해 입력 두 개가 어디서 왔는지 보이게 합니다.
- 같은 상황을 그 노트북 안에서 계속 확장합니다(과일 하나 → 과일 N개 → 점수 K개). 상황을 절마다 바꾸지 않습니다.
- MNIST 그림은 상황을 익힌 **뒤에** "같은 계산을 이미지에서 보면"으로 붙입니다. 이미지가 먼저 나오면 화소·784 같은 숫자가 또 하나의 낯선 말이 됩니다.

## 4. 문장

- 한 문장에는 생각 하나. 수식 다음 줄에는 그 수식을 말로 읽은 문장을 둡니다.
- "다음 노트북에서 다룹니다"처럼 미루는 말은 그 자리에서 **왜 지금 필요 없는지**를 한 마디 붙입니다.
- 숫자 범위는 `0–9`, `1부터 4까지`로 씁니다. 물결표는 취소선으로 렌더링될 수 있어 쓰지 않습니다.

## 5. 연습 형식: 코딩 테스트처럼

연습은 **함수 뼈대를 주고 핵심 한두 줄만 채우게** 합니다. 나머지 코드(모양 검사, 반환, 보조 계산)는 미리 써 둡니다.
읽는 사람은 그 절의 "가져갈 것" 한 줄을 코드로 옮길 수 있는지만 확인하면 됩니다. 어려운 문제는 두지 않습니다.

```python
def exercise_affine(X, W, b):
    assert X.shape[1] == W.shape[0]
    ### 이 주석 아래에 다음을 구현하세요.
    ### 구현할 내용: X @ W 에 b를 더한 Z (모양 (N, K))
    ### 힌트: 4절의 affine 함수 한 줄입니다.
    raise NotImplementedError
    return Z
```

- 채울 자리에는 `raise NotImplementedError` 한 줄을 둡니다. 읽는 사람은 이 줄을 지우고 코드를 씁니다.
- 검사는 `run_check(check_함수, exercise_함수, hint=...)`로 합니다. 아직 채우지 않았으면 안내문만 출력하고 노트북은 계속 실행됩니다. 값이 다르면 "값이 손계산과 다릅니다"를 출력합니다. 맞으면 검사 함수의 통과 메시지가 나옵니다. `run_check`는 값을 돌려주지 않으므로 검사 셀 아래에는 그 메시지만 보입니다(2026-09-13까지는 반환값 `False`가 함께 표시됐습니다).
- 검사 함수는 작은 손계산 값과 비교합니다. 한 문제에 검사 하나입니다.
- 연습 셀 바로 뒤에 `<details><summary>정답 보기</summary>` 블록으로 정답 한두 줄을 접어 둡니다. 막히면 펼쳐 보고, 다시 접고 스스로 써 봅니다.
- 함수 이름은 `exercise_`로 시작합니다. 노트북 끝의 준비도 질문은 그대로 둡니다.

**절 연습 (2026-09-16 사용자 요청).** 노트북 끝의 연습 A–D에 더해, **🔑 최상위 절마다 그 절의 끝**(다음 `##` 제목 바로 앞)에 연습 하나를 둡니다.
실제로 공부해 보니 끝의 연습에서 공부가 되더라는 관찰에서 나온 규칙이라, 절을 읽은 직후 그 절의 한 줄을 스스로 써 보게 하는 것이 목적입니다.

- 제목은 `### ✏️ 연습 N · 제목`(N은 절 번호, 소절 둘이면 `5-1`·`5-2`)입니다. 노트북 끝의 연습은 A·B·C·D 글자로 남겨 둘을 구분합니다.
- 시험 대상은 그 절의 **"이 절에서 가져갈 것"** 문장입니다. 끝 연습 A–D가 이미 그 한 줄을 묻고 있으면 절 연습은 다른 각도(반복문/벡터화, forward/backward, 다른 축, 한 표본만인 경우, 역연산, 크기 공식, 🔍 "바꿔 보기"의 계산)를 고릅니다.
- 연습 셀은 그 자리보다 **위에서 정의된 이름과 NumPy만** 쓰고, 뒤 셀이 쓰는 전역 상태(기존 변수, 본문 `rng`)를 바꾸지 않습니다. 검사용 배열은 검사 함수 안에서 만듭니다.
- 노트북의 첫 절 연습에만 푸는 법 문단(`nbedit.HOW_TO_SOLVE`)을 붙입니다. 네 셀(✏️ 제목·안내 / 뼈대 / 검사·`run_check` / 접힌 정답)은 `scripts/nbedit.py`의 `exercise_cells`로 만들고 `insert_before(nb, "## 🔑 3. ", cells)`처럼 **다음 절 제목**을 key로 끼웁니다.
- 셀을 끼우면 뒤 셀이 정의에서 멀어지므로 `check_code_comments.py`가 새로 보고하는 이름에는 `# 쓰는 것:` 줄만 더합니다(출력 불변).

## 7. 코드 주석: 다는 자리를 정해 둡니다

읽는 사람은 Python의 변수·함수·반복문은 읽지만, NumPy 관용구와 "이 변수가 어디서 왔는지"에서 멈춥니다.
주석은 줄마다 달지 않고 **아래 여섯 자리**에만 답니다. 앞의 마크다운 셀이 이미 말한 것을 코드에서 되풀이하지 않고, 주석 줄은 코드 줄의 1/3을 넘지 않게 합니다.
수식·구현·검산·실험 설정은 바꾸지 않되, **출력이 같은 가독성 재작성은 허용**합니다(D-013). 재작성 뒤에는 새 커널에서 실행해 출력 문장과 그림이 같은지 비교합니다.

1. **모든 `def`에 docstring** (1–3줄): 무엇을 하는지, 대응 수식, 입력·출력의 모양 순서입니다. 연습 뼈대(`exercise_*`)와 검사 함수(`check_*`)도 한 줄 docstring을 둡니다.

   ```python
   def gradient_on(idx, w, b):
       """idx로 고른 표본들만의 기울기. 01번의 dW = X.T @ dZ, db = dZ.sum()과 같은 식입니다 (dZ = residual / B).
       idx: (B,) 정수 배열, w: (784,), b: 숫자 → (dW: (784,), db: 숫자)."""
   ```

2. **셀 첫 줄의 "쓰는 것"**: 다른 절이나 네 셀 이상 위에서 만든 이름을 쓰는 셀은 첫 줄에 `# 쓰는 것: X, T, N (📎 데이터 셀) · w0, b0 (1절)`로 출처를 적습니다. 전역 이름을 쓰는 함수는 docstring 바로 아래에 둡니다. 그림 호출만 있는 셀은 예외입니다.

3. **관용구는 먼저 쉬운 형태로, 안 되면 코드 상자로.** 출력이 같으면 바꿉니다: `-(-N // B)` → `math.ceil(N / B)`, 한 줄의 `a; b` → 두 줄, `lambda` → 이름 있는 `def`, `assert a and b` → 주장별 `assert`, 정의와 실행·검산이 한 셀 → 두 셀. 바꿀 수 없는 관용구(`_`, 컴프리헨션, `[:, None]`, `rng.integers`, `rng.permutation`, 슬라이스, `np.corrcoef(...)[0, 1]`, `zip`, `np.stack`)는 처음 나오는 마크다운 셀에 용어 상자와 같은 형식의 **코드 상자**로 풀이하고, 코드에는 짧은 줄 끝 주석만 둡니다.

   ```markdown
   > **코드**
   >
   > - `rng.integers(0, N, size=8)`: 0부터 N−1까지의 정수 8개를 무작위로 뽑습니다. 같은 번호가 두 번 나올 수 있는 **복원추출**입니다.
   ```

4. **검산에는 주장 문장**: `assert 조건, "…이어야 합니다"`. `np.testing.assert_*`는 줄 끝에 `# 검산: 무엇 = 무엇`. 검산만 있는 셀은 마지막에 `print`로 통과를 보여 줍니다. 통과한 assert는 아무것도 출력하지 않기 때문입니다.

5. **한 셀 한 역할, 코드 25줄 이하**: 정의 / 실행·검산 / 실험 / 그림을 다른 셀에 둡니다. 여러 단계가 한 셀에 있어야 하면 `# 1. 예측과 잔차`처럼 단계 번호를 붙입니다. 클래스 하나나 함수 하나뿐인 정의 셀은 셀로 나눌 수 없으므로 25줄을 넘어도 두되, 안에 단계 번호 주석을 둡니다(13번 `Node`, `check_matmul`).

6. **주석의 내용 순서는 모양 → 수식 항 → 이유**: `# (784,): 표본별 기울기 r_n·x_n 을 B개 평균한 것`처럼 shape을 먼저, 그다음 어느 식의 어느 항인지, 필요하면 왜 이 값인지. 코드를 그대로 말로 옮긴 주석(`# 반복문 시작`)은 두지 않습니다.
