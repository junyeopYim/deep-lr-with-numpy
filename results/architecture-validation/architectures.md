## 계산 검산

각 함수의 입력·상태·파라미터를 중심차분과 비교했습니다. 전체 검사의 최대 상대오차는 약 **2.97×10⁻⁸**, 통과 기준은 2×10⁻⁶입니다.
이는 지정한 작은 입력들에 대한 검사이며 모든 가능한 입력에 대한 형식적 증명은 아닙니다.

| 단위 | 직접 확인한 경로·성질 | 대표 최대 상대오차 |
|---|---|---:|
| CNN | 반복문/패치 행렬곱, stride·padding, dX 겹침 누적, pooling, 전체 분류기 | 8.05×10⁻¹⁰ |
| RNN | 모든 시각 상류, 초기 h, 시간별 공유 미분 합, 스칼라 시간 미분의 곱 | 2.14×10⁻¹⁰ |
| LSTM·GRU | 두 상태·세 게이트·후보 경로, 초기 상태와 3스텝 BPTT | 3.62×10⁻⁹ |
| Attention | 직사각형 Q/K/V, softmax 행 미분, mask, 학습된 투영·head | 2.97×10⁻⁸ |
| Transformer | LN epsilon·gamma, MHA 네 투영, 잔차·FFN, 반복 embedding·위치·head | 1.49×10⁻⁹ |
| GNN | 방향·고립 노드, 합·평균, 두 층·readout·head, 순열 forward/backward | 5.58×10⁻¹⁰ |

mask의 금지 확률 0, 허용 행 합 1, 미래 변경에 대한 과거 출력 유지도 확인했습니다.
GNN은 노드 순열에 대한 출력·입력 미분의 대응과 그래프 출력·공유 파라미터 미분의 불변을 검사했습니다.
상수 특성에서 평균 집계가 path/star를 구별하지 못하는 경우와 합 집계가 6고리/분리된 두 3고리를 구별하지 못하는 경우도 계산했습니다.

### 발견한 문제와 반영한 수정

| 발견 | 수정·확인 |
|---|---|
| CNN 검사기의 zip이 빈/부분 반환을 통과시킴 | dX·dK·db를 명시적으로 분해하고 shape 확인. 후속 독립 실행에서 빈/부분 반환과 덮어쓰기 오답 거부 |
| CNN stride·내림과 수치미분용 스칼라의 연결 부족 | stride/내림 뜻, L=ΣY⊙G와 상류 G의 관계 설명 |
| RNN h0 미분과 그림의 입력 미분의 지수 차이 | w^T와 wx·w^(T−t)의 경로 설명 |
| LSTM 초기 forget gate를 bias만의 상수로 읽을 수 있음 | 입력·이전 상태의 affine 항이 0일 때라는 조건과 실제 샘플별 gate 구분 |
| Attention 검사 실패 메시지에 위치·오차가 없음 | mask 조건·배열명·오차를 함께 표시 |
| Transformer 잔차 설명이 실제 코드와 다른 줄을 지칭 | 실제 두 합의 항등 경로를 가리키도록 수정 |
| 배치별 MHA mask의 배치/head 축이 조용히 섞일 수 있음 | `(N,1,T,T)` 안내, 잘못된 3차원 mask 거부, 배치별 금지 확률 검산 |
| GNN 선형 readout 한계의 조건이 빠짐 | 상수 노드 특성 조건과 잡음 특성을 구분 |
| zero-in-degree 노드와 고립 노드 혼동 | 들어오고 나가는 edge가 모두 없는 실제 고립 노드를 검사에 추가 |
| 일렬 그래프 노드가 자동 y축 범위에서 잘림 | 좌표 범위의 여백을 명시하고 실제 PNG의 모든 노드·번호를 재확인 |

최종 09는 새 실행자에게 현재 산출물만 제공해 다시 실행했습니다. 본문 코드 18개와 원래 그림 5개·변형 그림 2개를 확인했고 차단·추측 0건이었습니다. 배치별/헤드별 mask, 독립 LN·block 미분, 반복 embedding, head 4개 학습을 재현했습니다. [최종 09 수치](rehearsal/09-final/metrics.json)에 기록했습니다.

최종 10도 새 실행자가 본문 코드 19개·PNG 5개를 실행·확인했습니다. 독립 layer backward와 전체 합/평균 모델의 최대 상대오차는 약 1.05×10⁻⁹, 순열 검사의 최대 절대차는 1.78×10⁻¹⁵였습니다. 완전 고립 노드, 8노드 변형, 의도적 오답 5종, 1–5층에서의 표현 한계 검산을 통과했고 학습 차단은 없었습니다. 최종 기록은 [10/최종 실행](rehearsal/10-final/execution.json)에 있습니다. 독립 점검 후 표제의 ‘세 종류’를 ‘공유 방식’으로 고치고 동일 코드를 다시 새 커널에서 실행했습니다.

```bash
python -m pytest -q
python scripts/verify_notebooks.py --suite foundation
```
